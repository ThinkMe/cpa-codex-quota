# Codex 余量桌面小部件

连接现有 **CLIProxyAPI v8.0.69**，在小米 HyperOS 桌面查看默认 Codex 账号的 5 小时与每周剩余额度。App 内保留全部账号及重置时间等详情。

小部件采用圆润的马卡龙风格：不透明纯白背景、无边框和大圆角，深色模式下仍保持白底。上下分别显示“5H限额”和“周限额”，每组采用标题与大百分比、全宽加粗胶囊进度条、重置时间的分层布局。常规字号为 14/22/11sp，轨道高 10dp；按可用宽高和系统字号自动选择紧凑档，宽度不足时优先显示“2小时后”等倒计时。默认约 2×2 格（保留 110×110dp 兼容尺寸声明，避免小米桌面额外占格），支持调整尺寸、5 分钟起的自动刷新，保留原有连接、默认账号和已设间隔。

## 安装与使用

1. 将 `app/build/outputs/apk/debug/app-debug.apk` 传到手机，安装 **Codex 余量**。这是可直接安装的调试签名版本。
2. 打开 App，填写服务地址，例如 `https://proxy.example.com`，以及登录管理后台使用的**管理密钥**。调用模型的 API Key 不能代替管理密钥。不需要在源代码中填写真实密钥。
   - 后台地址为 `https://你的域名/management.html` 时，可填写 `https://你的域名`。使用 IP 时填写 `http://服务器IP:端口`，协议和端口与实际服务一致。手机不要填写 `localhost` 或 `127.0.0.1`。
   - 管理密钥无需添加 `Bearer ` 前缀。编辑已有连接时，密钥留空表示沿用已保存密钥；更换服务器必须填写对应管理密钥。
   - 输入自动保存为本机草稿，草稿密钥加密保存。填写错误、连接失败、收起表单或关闭应用后，仍可继续修改；再次打开时有草稿会自动展开连接表单。草稿不参与后台刷新，连接成功后才替换正式配置并清除草稿。
3. 点击“保存并连接”，立即查询全部未禁用账号。在“桌面设置”选择默认账号，或在账号详情中设置默认账号及本地名称。所有小部件只显示同一个默认账号。
4. 设置自动刷新间隔：5、10、15、30、60、120 分钟、自定义整数分钟（至少 5 分钟），也可以关闭。初始默认 30 分钟，修改后从新间隔重新计时，重新打开 App 不重置计时。
5. 点击“添加到桌面”，在系统弹窗确认；也可以长按桌面，从小部件列表添加“Codex 余量”。新小部件默认约 2×2 格，长按可调整大小。已有小部件保留原尺寸，可手动缩小。
6. 点击小部件任意位置执行“刷新数据”，只查询默认账号；按压时显示蓝色扩散波纹，整卡背景播放约 1.6 秒一轮的蓝青色斜向扫描光束，两条额度进度条显示亮点与渐淡拖尾，周进度条错后约 160ms。文字始终位于光效上方，0% 和未知数据保留空轨道，短填充区简化或隐藏粒子。底部时间行原位显示小转圈和“刷新中”，成功后光晕约 240ms 淡出，小对勾同步描画，并显示“已更新”约 1 秒，再恢复时间。刷新等待至少展示约 0.7 秒，期间合并重复点击，并复用正在执行的刷新任务。只有被点击的小部件显示扫描光束、粒子及原位状态，其他实例和后台自动刷新采用进度条呼吸反馈。无连接或有效默认账号时打开 App 配置。App 内“刷新额度”仍查询全部未禁用账号，账号详情从 App 内进入。

多个小部件实例共享服务器、默认账号、刷新间隔和缓存。最后一个小部件移除或关闭自动刷新后，停止周期查询；手动刷新仍可使用。旧版本的多选配置会迁移到首个已选且未禁用账号，没有可用已选项时采用首个可用账号；迁移后，默认账号被移除或禁用时不会自动换号。

## HyperOS 后台设置

在“设置 → 应用设置 → 应用管理 → Codex 余量”中，允许应用自启动，并将省电策略设为“不限制”（菜单名称随系统版本略有不同）。App 中“使用说明 → 打开应用信息”可进入应用设置。

自动更新由 WorkManager 按设置间隔尝试调度；5～14 分钟使用连续单次任务，每次完成后等待所设间隔再安排下一次，15 分钟及以上使用周期任务，系统省电、休眠和网络状态可能使其延后。手动刷新不依赖周期调度，无需常驻通知和精确闹钟权限。

## 额度含义与错误处理

- “剩余”是对应额度窗口的百分比，由 `100 − used_percent` 计算；不是剩余 Token 数或剩余请求次数。
- 根据 `limit_window_seconds` 识别 5 小时、每周等窗口；接口没有提供的字段显示“—”，没有窗口时说明“接口未提供主额度窗口”。
- App 内重置时间使用手机时区。到达重置时间后不会自行把额度设为满额，需等查询成功。
- 刷新失败时保留上次成功的额度和时间。账号错误在该账号下显示；服务连接错误在顶部显示。一个账号失败不会阻断其他账号。
- 小部件百分比数字、进度条及呼吸动画按原始剩余额度统一变色：小于 30% 为红色 `#C65746`，30% 至 70%（包含端点）为黄色 `#E0AA14`，大于 70% 为绿色 `#10B981`。无数据或对应窗口缺失时保留深灰色“—”和空轨道。
- 小部件时间戳使用手机时区，格式为“MM/dd HH:mm · 2小时后”；窄尺寸优先保留倒计时；极小尺寸及大字体组合下，先简写标题为“5H”和“周”，必要时隐藏可见时间，无障碍描述仍保留完整标题和时间。倒计时每次重绘时重新计算；到期显示“待刷新”，不会自动补满额度。
- 手动刷新失败时停止扫描与粒子，在底部原位保留红色“刷新失败，点击重试”，窄尺寸使用“失败，点击重试”；极小尺寸在周标题旁显示错误图标，图标位置始终预留以避免布局移动。可立即点击重试，保留上次额度缓存，后续刷新成功后清除错误提示；无障碍描述同步状态，错误详情在 App 中查看。
- 账号重新授权或被移除后，可点击“刷新额度”同步列表；默认账号不可用时需在 App 中重新选择。
- 第一版聚焦 Codex 的主额度窗口，不包含代码审查额度、额外积分余额及其他供应商。

## Android Studio 开发

直接打开本目录并等待 Gradle 同步。工程使用 AGP 9.1、Gradle 9.3.1、内置 Kotlin、Compose、Glance、WorkManager 和 DataStore；最低 Android 8.0（API 26），编译及目标 API 为 36。

- 使用 JDK 17～25，当前环境已通过 Android Studio 自带 JDK 25 构建。
- SDK 位置在本机 `local.properties` 中，例如 `sdk.dir=E\:/Tools/AndroidSdk`；该文件不应提交。
- Gradle 分发包使用可访问的镜像，并固定官方 SHA-256 校验值；Android 和 Maven 依赖使用官方仓库。
- PowerShell 构建：`powershell -ExecutionPolicy Bypass -File .\build.ps1`。
- 构建、单元测试及 Lint：`powershell -ExecutionPolicy Bypass -File .\build.ps1 -Check`。
- 已设置 `JAVA_HOME` 时也可运行：`./gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`。

输出：

- APK：`app/build/outputs/apk/debug/app-debug.apk`
- 单元测试报告：`app/build/reports/tests/testDebugUnitTest/index.html`
- Lint 报告：`app/build/reports/lint-results-debug.html`

## 接口与本地数据

1. 使用管理密钥请求 `GET /v8/management/credentials`，筛选 Codex 账号，取得 `auth_index` 和账户 ID。
2. 请求 `POST /v8/management/requests/api-call`，由服务代查 `https://chatgpt.com/backend-api/wham/usage`。内层使用 `Bearer $TOKEN$` 占位符和对应 `Chatgpt-Account-Id`，服务器注入账号令牌。
3. 检查代查响应中的 `status_code`，再解析 `body` 中的额度窗口。外层 HTTP 200 不等于查询额度成功。

手机直连你的服务器，不引入额外中转服务。支持保留反向代理路径前缀，支持明确填写的 HTTP 地址，未填写协议时默认 HTTPS。HTTPS 使用系统证书验证；重定向需改为填写最终服务地址。

管理密钥及草稿密钥使用 Android Keystore 的 AES-GCM 密钥加密，DataStore 保存地址、密钥密文、账号显示配置及额度缓存。密钥输入不进入明文页面恢复状态，应用不输出网络请求内容。备份与设备迁移均排除应用数据。各账号登录令牌由服务器管理，手机不下载认证文件。

## 验证范围

单元测试覆盖账号筛选、百分比换算、窗口与重置时间、缺失及异常字段、缓存恢复、v8 请求路径、鉴权占位符、管理密钥错误、上游错误和重定向处理，以及旧多选配置迁移、默认账号失效、刷新间隔校验和恢复、额度按时长识别。小部件使用单账号布局，不再生成滚动列表编号。

模拟器检查与真实 HyperOS 验证应分开看待：模拟服务可以验证应用行为，真实账号的余量仍需在手机填写你自己的地址和密钥，与现有管理后台核对。后台保活和桌面尺寸以实际 HyperOS 桌面为准。

独立测试模拟器上可运行 `python tools/verify_emulator.py --adb E:\Tools\AndroidSdk\platform-tools\adb.exe`。脚本会清空该模拟器中的本应用数据，启动本机模拟接口，验证双账号查询、密钥加密、错误缓存、桌面添加、手动刷新后的数值变化、深浅色显示与进程重启。仅允许操作模拟器，结果和截图输出到 `build/verification/`。

增加 `--settings-only` 可单独验证本次桌面设置：自定义间隔校验、WorkManager 实际周期与取消状态、重启保留计时、默认账号切换、多实例同步和桌面刷新范围。

使用 `python tools/generate_widget_effects.py` 可重新生成扫描光束、粒子与完成动画资源；动画由桌面宿主播放，不逐帧重绘小部件。Android 12 及以上按卡片真实圆角裁剪，旧版 Android 使用更保守的矢量圆角内裁剪，避免光束溢出。

刷新反馈独立持久化本轮请求结果，不依赖周期任务的最终状态或输出。周期任务完成后重新排队也会及时结束扫描；进程重启会恢复收尾任务，升级前遗留的等待状态可根据本轮已保存的额度恢复。使用 `python tools/verify_widget_feedback.py --periodic-only` 可在独立模拟器验证真实周期任务复用、失败及结果恢复。
